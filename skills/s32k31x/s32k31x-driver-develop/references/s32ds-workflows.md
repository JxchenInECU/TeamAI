# S32DS 3.6.6 工程操作

## 分析已有工程

1. 盘点工程内所有 `.mex`、`.project`、`.cproject`、`.settings`、链接资源、生成目录、启动代码、链接脚本、RTD 依赖及当前 build configuration。不自动挑第一个 `.mex`。
2. 对当前配置运行 `mex_tool.py inspect`，结合源码调用识别实际启用的功能。工具显示关闭的配置也要检查是否由应用/其他驱动接管。
3. 检查 processor/package/core/预处理宏、链接脚本容量、SDK 路径是否一致。读取 `generated_project_files` 和项目记录，再与当前工具预览、磁盘文件交叉核对实际输出位置；不能固定认为总在 `board` 或 `generate`，也不能把旧生成清单视为当前产物。
4. 按配置检查表分析时钟、路由、驱动、IRQ/DMA/触发及初始化。报告原始值、计算所得值、依据和未知项。只读分析不触发 Update Code，避免迁移或文件重写。

## 修改已有工程

1. 保存基线：版本控制 diff 或时间戳备份、`.mex` 哈希、生成目录及手写初始化的状态。保留用户未提交改动。**修改前做构建预检**：解析活动 build configuration 的 SDK 路径和预处理宏，核对关键公共头能否从实际 include 路径解析；按 `OsIf_Cfg.h`/源码确认是否引用 FreeRTOS 或 CustomTimer 并检查头文件、实现和链接输入；检查 `main`/启动入口是否真的调用生成的初始化。报告现存阻碍，区分同版本 SDK 绑定缺口、业务代码/RTOS 缺口与本次配置问题，不默认升级 SDK 或改换 RTOS。
2. 形成明确变更映射。单项参数可能涉及多个模块，例如改 UART 速率会用到 kernel clock；改 ADC 周期触发还要核查定时器和触发链。
3. 双击工程 `.mex` 或工程右键 `S32 Configuration Tools` 进入 Pins/Clocks/Peripherals。根据实际 UI 配置；不要用旧版截图坐标盲点。
4. 查看真实 Problems/工具校验。解决本次变更引入的问题；原有无关问题单独记录。
5. `Update Code > Open Update Code Dialog` 检查将创建/变更的文件、目标路径和选中状态，再生成。对原已存在的非生成代码保留用户实现。
6. 比较 `.mex` 和生成代码；确认目标参数生效、未被生成器还原。检查驱动组件依赖、include、宏、链接脚本及初始化调用。
7. 构建目标配置，保留退出码、日志、产物路径。若有硬件且明确要求测试，再做对应串口/总线/波形/采样等验证。

将配置生成、单文件编译、全工程链接、板端验证分别记录；前一级成功不抵消预检中已知的后一级阻碍。

如果只有静态编辑能力，可交付候选补丁与检查结果，但标记“待 S32DS 重新加载、校验、生成和构建”。不把单纯 XML 格式正确称为“配置正确”。

## 生成策略变更与交付验收

适用于合并 MEX、增删或复制功能组、切换组件生成方式以及调整生成/发布目录；普通单项参数修改仍按上面的修改流程执行。

- **按用户实际使用方式验证。** 交付给用户在原工程中直接 GUI 使用的配置，应实际加载正式 MEX，审阅 Update Code 详情并完成一次 GUI Update Code，核对受影响工具的校验结果和落盘文件。只有 CLI 导出证据时，记录为 CLI 验证；GUI 步骤无法完成时明确其尚未验证。用户明确采用仅 CLI 工作流时不强制额外 GUI 验证。
- **检查整个生成影响范围。** 从当前组件模型确认生成策略的作用域，例如 `FunctionalGroups` 可能同时改变多个 Peripherals 模块的输出。建立“模块/功能组 → 文件名、配置符号、默认初始化”的对应关系，复核相关 Pins 默认组及跨工具依赖。配置值相同仍须检查旧初始化代码、头文件和链接引用是否兼容。分别说明生成、发布、业务工程同步的范围；局部发布可以保留，但应明确适用工作流及未覆盖范围，不能据此宣称整工程 GUI 更新已经通过。
- **隔离历史文件查找。** 备份、往返样本和临时生成文件优先放在正式工程树之外。确需留在工程内时，根据当前 IDE 的实际文件查找方式设置并验证 Resource Filters 等隔离机制；只排除编译源不能证明同名文件不会参与生成定位。过滤格式须符合当前 IDE，外部修改工程描述后确认 IDE 已加载，必要时保存配置并刷新或关闭/重新打开项目，再检查历史目录确实不参与查找。
- **核对清单与最终文件。** 按 [生成文件清单与实际输出](mex-format.md#生成文件清单与实际输出)比较正式 MEX、GUI/工具更新预览和磁盘输出，审查创建、覆盖、删除或重命名的文件以及更新开关。生成后确认相关公共外设文件完整、输出位置符合交付目录设计；涉及生成后补丁时再验证补丁与重生成步骤。

## 新建 S32DS 工程

1. 确认目标 MCU、封装、板卡/接线、实际外部时钟、输出目录、RTD 层级与版本、编译器和功能需求。安装盘点中的设备枚举只是候选支持情况。
2. 在 S32DS 使用 `File > New > S32DS Application Project`，指定不以数字开头、只含拉丁字母/数字/下划线的项目名，选择目标 processor、core、已安装受支持的工具链。SDK 选择以向导实际页面为准。
3. 如果向导无目标 MCU/SDK，检查安装包与软件包兼容性；不要先选 S32K344 再全局替换成 S32K312。缺包明确报告所需包和已有版本。
4. 有目标型号匹配的官方示例时，可用 `File > New > S32DS Project from Example`。示例必须通过 S32DS 创建/导入到用户目录，不直接改安装目录。
5. 工具生成 `.mex` 后核对 processor、package、core、mcu_data；精确封装可能在配置工具里选择。时钟、Pins、Peripherals 按需求配置，选择正确 IP/高层模块和依赖。
6. Update Code。用当前 RTD 文档和例程接入必要初始化/ISR/回调，检查链接脚本及芯片宏后构建。
7. 交付完整工程和可复现步骤。记录实际创建方式；模板来源可参考其他型号的 API，但其时钟/引脚/内存/外设配置须按目标重新核实。

## 验收及失败处理

| 层次 | 成功证据 | 不代表 |
| --- | --- | --- |
| 静态 | XML 可解析、身份一致、变更范围合理、资料核对完成 | UI 接受、时钟解算/所有依赖有效 |
| Config Tools | 实际加载/校验日志、生成的新文件和差异 | 工程一定链接成功 |
| Build | 目标构建日志、退出码、当前 ELF/map | 板级功能和时序实测 |
| Hardware | 板卡/接线、固件、测量条件及观测结果 | 其他板卡/封装同样成立 |

异常先按日志区分：缺 MCU 数据/SDK、工具版本不兼容、路径或工作区占用、配置错误、应用代码/链接错误。修复明确原因后重试，反复出现同一工具故障时保留日志和候选变更，说明具体未完成步骤，不重复盲试。

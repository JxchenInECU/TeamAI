# s32k31x驱动开发

使用中文沟通，保留工具界面、驱动 API 和配置项的原始英文名称。按用户请求范围完成分析、配置或答疑；分别报告实际达到的静态、工具生成、构建和硬件验证等级。

## 范围与随附资料

- 当前支持范围：S32K310、S32K311、S32K312、S32K314。其他型号先说明超出本技能当前范围，不默认为同配置兼容。
- 工程创建使用 **S32DS**；配置源是 **`.mex`**。不要手写 Eclipse 工程骨架或把单独生成的 C 文件当作已创建的 S32DS 工程。
- 随附资料位于本技能的 `assets/data/`，入口为 [数据资产清单](assets/data/数据资产清单.md)；PDF、XLSX 与章节索引随技能一起迁移。
- 外部 S32DS 安装位置、资料选择及已观察版本见 [本地资料与证据](references/local-sources.md)；它们是盘点记录，不代替当前安装检查。用户提供路径时优先使用并验证该路径。

## 建立上下文

从现有工程获取任务所需的活动 `.mex`、目标型号/封装/core、构建配置、S32DS 与 RTD/SDK 版本、板级时钟和接线，以及目标外设的速率、中断/DMA 等要求。缺失信息只询问会影响当前结论的部分；概念答疑无需完整工程。可用 `inspect_environment.py`、`mex_tool.py inspect` 辅助盘点，但静态结果不等于工具校验。缺封装或晶振时可给条件化方案，不把候选写成已核实配置；新建工程缺目标型号时先整理需求，型号确定后再创建。在新建工程或者修改已经配置时，不清晰的需求先询问，避免在不完整信息下做出假设，不允许基于假设做出配置。

## 证据与关键约束

- CAN/CanIf 配置先区分 S32DS 配置工程的生成依赖组件与实际业务工程的 CanIf 实现；简化组件的一 HRH 一 RxPdu 映射不能推断为完整 CanIf 的能力限制。接入原则见 [CAN 与 CanIf 接入](references/driver-checks.md#can-与-canif-接入)。
- 用具体型号、封装、资料修订与 SDK 版本限定结论；型号能力查 Data Sheet、RM 的 chip-specific 小节、附件和适用勘误，字段/API 查本机相应版本的模型、头文件或帮助。不能套用相邻型号的资源、IRQ、DMA 或引脚事实。
- 给关键结论留下可定位来源；资料冲突时说明冲突并核实适用版本，不猜一个值。需要最新勘误或本地缺失资料时查 NXP 官方来源。
- 保留原工程驱动层级、RTD 版本及生成策略，除非用户要求迁移；RTD 的 IP 层不等于完整 MCAL 工程。字段候选值来自目标型号和当前组件的枚举/资源表；UI 标签、时钟树节点、MCAL 枚举及寄存器名不能因拼写相近而互换。
- `.mex` 的 `<dependencies>` 中 `description` 是约束描述，**不是已触发的错误日志**。工具 `enabled=false` 不等于整个工程没用该外设，可能在其他模块或应用代码中配置。

## 修改闭环

合并 MEX、改变功能组或生成策略时，按 [生成策略变更与交付验收](references/s32ds-workflows.md#生成策略变更与交付验收)分别核对配置数据、生成影响范围和正式工程再生成能力；CLI 隔离导出通过不等同于 GUI Update Code 已验证。

1. 记录原文件哈希/备份和已有用户修改。建立“需求 → 界面字段/XML 路径 → 原值/目标值 → 依赖 → 证据”映射。
   修改前做与目标工程相称的构建预检：SDK 绑定、构建宏、关键公共头、实际使用的 RTOS/CustomTimer 依赖和启动初始化入口；把既有阻碍与本次配置问题分开。
2. 核查本次涉及的外设、时钟、引脚、驱动、IRQ/DMA/触发与初始化链，只改变需求及必要依赖。改变硬件对象数组或跨模块引用前，按 ECUC 规范用当前安装工具在隔离副本完成基线导出→导入→再导出，保持版本检查开启。
3. 优先在 S32 Configuration Tools 修改；已核实的小范围 XML 修改可按 MEX 规范做。不要只改 `clock_output` 等显示结果而不改真实源/分频参数。
4. 写回前按完整 XML 子路径白名单审查差异，包括目标模块内部未授权字段。保存后在 S32DS 重新加载、校验并 Update Code，检查生成文件及更新开关；版本自动升级造成的大面积变动单独解释。CLI 结果还须核查目标模块错误、进程完成和预期产物，返回码 0 不单独算通过。
5. 对受影响部分完成可执行的工具与构建验证，并按证据分别报告：**静态 / Config Tools 生成 / 编译与链接 / 硬件实测**。若既有 SDK、RTOS 或业务代码阻碍全工程构建，继续完成不依赖该阻碍的配置验证，明确未通过的层次和原因；不因本次配置任务擅自升级 SDK 或迁移 RTOS。

禁止修改安装目录内的官方示例、RTD 源或厂商数据。生成目录中的手工改动先辨认用途；可覆盖区域和用户代码区分开处理。不能为了生成成功删除约束、禁用检查或随意覆盖 SDK 文件。

## 新建工程与工具能力

使用 S32DS 的 `S32DS Application Project` 向导选择精确 MCU、core、受支持工具链及 SDK；仅在同型号示例确实存在时选 `S32DS Project from Example`。之后配置 `.mex`，Update Code，接入初始化并构建。

先发现当前会话可用的桌面工具或本机受支持自动化接口。若可操作 S32DS，则完成实际创建；若只能运行已验证的 CLI，则使用其支持的生成/导入/构建功能。**CLI 导入工程或导出 MEX 不等于创建完整新工程。** 缺少桌面操作能力且没有经文档证实的创建接口时，完成需求表和精确向导步骤，明确卡在创建步骤，交由用户在 S32DS 创建基线后继续。不要声称已自动建好工程。

授权范围内的分析、修改和验证连续完成，无需每步再询问。烧录、擦除、HSE/密钥、OTP/eFuse、永久调试锁定不包含在普通配置任务内；仅在明确任务授权和具体参数充分时处理。

## 交付表达

结论先行。工程变更列出改动文件、行为、必要依赖、差异、已运行验证和未完成项；答疑说明适用型号与条件、来源和检查方法。按需要使用配置表，不把内部 XML 字段名猜成界面标签。
